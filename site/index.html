Divert packets.
Filter them like Wireshark.

Avulse captures network packets so a program can inspect, drop, modify or re-inject them. It covers what WinDivert does, adds an Ethernet layer, and speaks the display filter language you already use in Wireshark, checked against tshark.

Try the filter playground Read the guide
CLI cargo install --locked --git https://github.com/ffalcinelli/avulse avulse-cli

Pre-alpha. The filter language and packet parser work today; packet capture is next. The crates.io and PyPI packages only reserve the name.

Filter playground

This is the real Avulse filter engine, compiled to WebAssembly and running in your browser. Type a filter: it is checked as you type and run against the sample packets below. Nothing leaves your device.

    Why Avulse
    
        
    
          
    
            
    Everything WinDivert does
    
            
    The same model: NETWORK, NETWORK_FORWARD, FLOW, SOCKET and REFLECT layers, flags,
              priorities, batching and asynchronous I/O, and a WinDivert-compatible shim so
              existing programs, pydivert and jdivert can move over unchanged.
    
          
    
          
    
            
    Plus an Ethernet layer
    
            
    See whole frames, including non-IP traffic such as ARP and LLDP, and VLAN tags.
              Filter on eth.*, vlan.* and arp.*.
    
          
    
          
    
            
    Wireshark filters, verified
    
            
    Filters are Wireshark 4.6 display filters. A differential test runs every field
              and hundreds of filters through tshark and Avulse, and the few
              differences are documented.
    
          
    
          
    
            
    Errors that help
    
            
    Strict types and spans in every message: a typo gets a “did you mean”, and a
              comparison that could never match is an error instead of a silent false.
    
          
    
          
    
            
    One engine, every kernel
    
            
    Parsing and matching are no_std Rust with no unsafe, and
              never allocate or panic on any input, so the same code runs in user space, the
              Windows driver and the macOS system extension.
    
          
    
          
    
            
    Exact in the kernel
    
            
    On Linux, filters will compile to eBPF at runtime and match in the kernel; on
              Windows and macOS, to verified bytecode. No more superset matching with a user-space
              re-check.
    
          
    
        
    
      
    
    
    

    
    
      
    
        
    Roadmap
    
        
    Avulse is built in phases, each with an exit criterion. See the
          design chapter and the full
          roadmap.
    
        
      
          
    1. 0
      Setup and spikes
      Workspace, CI, names. eBPF codegen, Rust Windows driver and macOS spikes are pending.
      2. 
          
    2. 1
      Parser and filter engine
      Done: parsing, the language, the evaluator, tshark validation, the CLI. Next: bytecode, the WinDivert front-end.
      3. 
          
    3. 2
      Linux packet layers
      NETWORK, NETWORK_FORWARD and ETHERNET through TC eBPF, with exact in-kernel matching.
      4. 
          
    4. 3
      Linux events, API v0.1
      FLOW, SOCKET and REFLECT; the first release of the Rust API and C ABI.
      5. 
          
    5. 4
      WinDivert compatibility
      The shim, validated by the pydivert and jdivert test suites.
      6. 
          
    6. 5
      Windows driver
      WFP callouts and an NDIS filter, signed.
      7. 
          
    7. 6
      macOS
      A Network Extension system extension, notarized.
      8. 
          
    8. 7
      Bindings and 1.0
      Native Python and Java bindings, benchmarks, a frozen API.
      9.
