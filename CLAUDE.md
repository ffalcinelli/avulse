# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Avulse is a cross-platform (Linux, Windows, macOS) packet-diverting library. It aims to be a superset of WinDivert: it adds an ETHERNET layer, uses a Wireshark-compatible filter language, and will ship a WinDivert-compatible shim so that pydivert/jdivert can move onto it. It is the fifth repo in `~/Workspace/divert/` (see `../CLAUDE.md` for its siblings: windivert, ebpfdivert, pydivert, jdivert). It is dual-licensed LGPL-3.0-or-later / GPL-2.0-or-later, and BPF programs must be GPL-compatible.

**Status: pre-alpha.** Only `avulse-proto`, `avulse-filter` (including its bytecode and WinDivert front-end), the `avulse filter …` CLI and `avulse-wasm` (the website's filter playground) are implemented, plus the `avulse` crate's handle API with its Linux backend for the packet layers (Phase 2 done: receive and send at NETWORK, NETWORK_FORWARD and ETHERNET, tun and IP tunnels included; Phase 3 Steps 14 to 17: the FLOW, SOCKET (refusing binds and connects in the kernel) and REFLECT layers; no other platform), `avulse-ebpf` (the Linux kernel side: TC programs, codegen, loader; Spike A in `docs/spikes/ebpf-codegen.md`) `spikes/windows-driver` as the Spike B prototype of the Windows driver (`docs/spikes/windows-driver.md`), and `spikes/macos`, Spike C's probes on GitHub's macOS runners (`docs/spikes/macos.md`). `crates/capi` (Step 18) is the C ABI, `libavulse.so`/`.a` with the hand-written header `include/avulse.h`. `crates/windivert-compat` (Phase 4, Steps 19 to 21) is `libavulse_windivert.so`, which exports libebpfdivert's C API over avulse so that pydivert and jdivert run on it unchanged. `bindings/python` is an empty placeholder that reserves the name. Versions stay 0.0.x while the project is experimental, and nothing is released before the Windows and macOS backends exist (owner decisions; the first release is v0.0.1). `docs/roadmap.md` is the design document (phases, the layer/backend feature matrix, filter-language decisions, and what to reuse from ebpfdivert). Read it before starting work on a new phase.

**Start each session with `docs/implementation-plan.md`.** It holds the current status, the accounts and workstation quirks (pushing over SSH, no `rustup`, cargo-fuzz through `RUSTC_BOOTSTRAP=1`), the open Wireshark-semantics questions, and the ordered next steps with acceptance criteria. Tick steps there as they land, and commit it together with the code.

## Architecture

### `no_std` is a hard constraint

`crates/proto`, `crates/filter` and `crates/abi` are `#![no_std]` (filter and abi use `alloc`) and `#![forbid(unsafe_code)]`. The same code is meant to run inside the Windows KMDF driver and the macOS system extension, so one engine gives one set of semantics everywhere. Do not add `std` or dependencies that need it. The optional `regex` feature (`matches`, via `regex-automata` with `alloc` only) keeps `no_std` too, but it is user space only: it is the one evaluation path that may allocate. Use `core::net` for IP types. Tests opt in with `extern crate std`. The `thumbv7em-none-eabihf` CI build is what enforces this.

### `avulse-proto`

`Packet::parse(bytes, Link::{Ethernet, Ip})` does zero-copy parsing of Ethernet, up to 2 VLAN tags (QinQ), ARP, IPv4, IPv6 (walking up to 8 extension headers, plus fragments), TCP (options through a bounded walk, `Tcp::option_iter`/`option`), UDP, ICMP and ICMPv6. Parsing **never fails, allocates or panics**: it stops at the first truncated or unknown header, and the rest of the buffer becomes the payload. `headers.rs` holds the per-header views, and `checksum.rs` handles recalculation.

### `avulse-filter`: the pipeline

`lexer` → `parser` (`ast`, `Display` = canonical `filter fmt` output) → `check` (name resolution of `let`/`$name` macros, strict typing, symbolic constants, lowering) → `ir::simplify` → `eval` (an allocation-free interpreter, the reference) or `bytecode` (for the kernels). `Filter::compile` / `Filter::matches(&Packet, &Meta)` is the public entry point; `Filter::program()` compiles to bytecode.

- **`value.rs` holds the semantics of values**: field loads (`load`, `load_layer`, `load_raw`), comparisons, set membership, `contains`, slices and every value operation. Both interpreters call it, so a semantic change goes there, once.
- **`bytecode/`** (`mod.rs` is the format spec: header, 8-byte instructions, tagged constant pool; `encode.rs`, `verify.rs`, `exec.rs`). `verify` and the interpreter use no `alloc` and must not panic on any input; jumps are forward only. `VerifiedProgram::matches_in` takes the register file (`Registers`, about 2.7 KiB) from the caller, for the Windows driver's short kernel stack; the interpreter borrows its operands (never copy `Vals` per instruction), and `scripts/stack-sizes.py` fails CI if a frame on its path passes 1 KiB. Field ids are indexes in `FIELDS`, so bump `bytecode::VERSION` when the field table or the encoding changes. A new IR node needs an opcode, a verifier rule, a disassembly arm and a row in the verifier tests. `src/tests/bytecode.rs` checks that the bytecode agrees with `eval` on every tshark table filter and on proptest-generated filters and packets; the `fuzz/` targets do the same from arbitrary bytes.
- **`windivert/` is the WinDivert 2.2 front-end** (`Filter::compile_windivert(src, layer)`, `avulse filter convert`): `parse.rs` (case-sensitive tokens, WinDivert's grammar and limits), `lower.rs` (each test to native IR, reproducing WinDivert's 128-bit signed comparisons, its `not` that flips one operator, and the compile-time folding of decided comparisons into protocol tests; tables of fields, layers and ranges in `mod.rs`). It reuses native IR nodes only, plus `Test::If` for `(a? b: c)`, so `ir::Test::native()` (`native.rs`) can print a native filter. `src/tests/windivert.rs` runs WinDivert's 241 vectors (generated table, `#[rustfmt::skip]`) through the IR, the bytecode and the native round trip.
- **Recursion is bounded on purpose.** The native parser limits nesting to `parser::MAX_DEPTH` (64) and the checker macro nesting to 4; the WinDivert parser keeps `and`/`or` flat and limits parentheses to 341. Every later pass recurses over the tree, and `deep_filters_are_bounded`/`windivert_deepest_filters` check the worst case. Keep new recursive code within these bounds.
- **`fields.rs` is the field registry.** The `fields!` macro generates both the `Field` enum and `FIELDS` (name, type, `Origin::{Wireshark, Extension, Flag}`, symbolic-constant table, description). To add a field, add a row there and the matching arm of `load` in `value.rs` (which reads the value from `Packet`/`Meta`). `UNSUPPORTED` and `APPLICATION` list Wireshark fields that are rejected with a hint because they need stream state or dissectors.
- **`labels.rs` is generated** by `scripts/gen_labels.py` from `tshark -G values`: Wireshark's value-string labels (`ip.proto == "TCP"`) for every Wireshark field, merged across Wireshark versions (labels change between releases; a label that means different values is ambiguous and rejected). Rerun it after adding fields with every tshark at hand, e.g. `python3 scripts/gen_labels.py tshark "docker run --rm -i <4.6 image> tshark"`; multi-table fields need an entry in its `TABLE`.
- **`meta.rs` (`Meta`)** carries everything that is not in the packet bytes: layer, event, direction, loopback, iface, process, and the flow tuple for the FLOW/SOCKET layers. `Layer` and `Event` keep WinDivert's numbering (`Ethernet = 5` is new).
- **Semantics follow Wireshark 4.6+ and are the main correctness risk.** Fields can have several occurrences (`ip.addr`, `tcp.port`, `vlan.id`, at most 4 values; see `MAX` in `value.rs`). `==` means some pair is equal, `!=` means no pair is equal, `!==` (`~=`) means some pair differs, `not in` means present and no value in the set, and any comparison with an absent field is false. An integer compared with bytes is one byte (`tcp[13] == 18` is 0x12). Type mismatches are compile errors, never a silent false. Diagnostics carry spans and "did you mean" help (`error.rs`).
- **`src/tests/tshark.rs` is the oracle.** It compares every Wireshark field and a table of filters with `tshark` over generated captures (`AVULSE_TSHARK=1 cargo test -p avulse-filter tshark`, needs tshark 4.6+). Add a row there whenever you add a field or change semantics; intentional differences go in its `DIVERGENCES`/`EXTENSIONS`/`STRICTER` tables and in the guide (`book/src/filters/wireshark.md`).
- The IR is the shared contract for the backends: runtime eBPF codegen on Linux with a superset-in-kernel fallback (`codegen::compile_superset`), and the bytecode verifier and interpreter in the Windows/macOS kernels. Keep it backend-neutral.

### `avulse`: the handle API and the backends

`Handle`/`OpenOptions` (`handle.rs`) check every argument with WinDivert's rules (priority range, exclusive flags, per-layer required flags, `Param` ranges, which layers send) and compile the filter (`Syntax::Native` or `WinDivert`) before calling the platform backend, so backends only see valid calls. `backend/mod.rs` holds the crate-private `Backend` (capabilities, open) and `Opened` (recv, send, shutdown, set_param, stats, `as_fd`, close) traits, and `platform()`, which picks the backend (`Unavailable` where there is none). The backends are modules of this crate (`backend/linux/…`, cfg-gated), not crates (on Linux, `avulse` also depends on `avulse-ebpf`, which must be published with it). `Address` (`crates/abi/src/address.rs`: `avulse-abi`, a `no_std` crate the Windows driver shares, holds it with `Flags`, `Param`, `Shutdown`, `Stats` and `Syntax`, and `avulse` re-exports them; `abi::ioctl` is the driver's IOCTL protocol, checked byte encodings) is `#[repr(C)]`, versioned (`ADDRESS_VERSION` 3, bump it with any layout change) and 216 bytes, with explicit fields, `Flow` (with the process name, 32 bytes) and `Reflect` (with the `Syntax` of the reflected filter) parts and the opaque 64-byte `Context` that backends fill for reinjection (at most its first 56 bytes: the compat shim keeps only those in WinDivert's union; Linux's `Ctx` asserts it fits); `crates/abi/src/tests.rs` pins the layout and the IOCTL encodings, and `crates/avulse/src/tests.rs` tests the checks on a fake backend.

The Linux backend (`backend/linux/`, Steps 8 to 12): `mod.rs` opens a handle (load an instance of the static programs, the matcher from `codegen` for the handle's `Env`: exact, else a superset, else match-all, and when it is inexact `Filter::matches` runs in user space, which reinjects what does not match; `SEND_ONLY` handles attach shut-down programs to `lo`'s ingress only, for the redirect; then, under the registry lock: reap, TC priority, configuration, attach to the selected interfaces plus `lo`, register; devices without a link-layer header (tun, WireGuard, PPP, ipip/ip6tnl/sit: `sys::Interface::link`) get the `avulse_*_ip` entry programs and serve the NETWORK layers only) and implements `Opened` (`recv` pops the queue, drains the ring buffer, or waits on an epoll fd of the ring and an eventfd). `record.rs` turns records into packets and `Address`es (it puts offloaded VLAN tags back, with their TPID from `M_VLAN_AD`, and its `Ctx` is the 64-byte reinjection context), `queue.rs` applies the queue parameters, `registry.rs` is the pinned registry (`/sys/fs/bpf/avulse/registry-1`, `flock` on `/run/avulse.lock`; bump the suffix if the entry layout changes; an entry keeps the filter as written and its `Syntax`, in byte 33), `heartbeat.rs` the per-process thread that keeps handles' configuration fresh (programs fail open after 3 s), `send.rs` the injection paths (raw IP socket for loopback and routed packets, `AF_PACKET` out of the capture interface behind the saved L2 header, or on `lo` with `MARK_REDIRECT | ifindex` for inbound packets; GSO through `virtio_net_hdr`; WinDivert's checksum and impostor-TTL rules), `sys.rs` the raw system calls, `reflect.rs` the REFLECT handle (Step 17: a periodic `timerfd` in the epoll set; every 100 ms it diffs the registry's live entries with what it saw, `reflect::diff`; the data is the filter as written, its language in `Reflect::syntax`), and `events.rs` the FLOW and SOCKET handles (Step 16: without SNIFF, `matchers` compiles the filter exactly for each `EventHook`, after checking with `codegen::decide_for` that it cannot match LISTEN or ACCEPT; Step 15: `Events` from `avulse-ebpf`, records to addresses with `Address::flow`, `UdpFlows` turning a UDP socket's release into DELETED for each of its flows, the filter evaluated in user space on an empty packet; `Rx<R>`, the queue, epoll and `recv` loop, is shared with the packet handle). Unit tests without privileges are in `backend/linux/tests.rs`; `tests/capture.rs` (`AVULSE_BPF=1`, root) is the privileged suite: real traffic over a veth pair, VLAN devices, `lo`, a tun device the test owns, an ipip tunnel and two namespaces routed through the host, ebpfdivert's integration scenarios, and the kernel against the evaluator. It runs in the VMs and, with `tests/kernel.rs`, in the `privileged` workflow on a GitHub Ubuntu runner (no substitute for the 5.15 VM). Order matters at open: the configuration must be written before attaching (the zero configuration diverts).

### `avulse-capi`: the C ABI (Step 18)

`crates/capi` builds `libavulse` (`cdylib` and `staticlib`, lib name `avulse`; no `rlib`, which would collide with the facade's, and the facade is the dependency `avulse-rs`). The header `include/avulse.h` is written by hand and is the API's documentation: keep it, `src/lib.rs` and the `_Static_assert`s at its end in step (`src/tests.rs` pins the same numbers on `avulse_address` and on `avulse::Address`). Calls return `AVULSE_OK` or negative `AVULSE_E_*` statuses (not errno, for Windows), with `avulse_last_error`/`avulse_last_os_error` per thread. `avulse_address` mirrors `Address` with integers for its `bool`s and enums, and converts field by field with checks, so no value from C is undefined behaviour. Functions are `#[unsafe(no_mangle)] unsafe extern "C"` with `# Safety` docs. `tests/c.rs` runs `cargo build -p avulse-capi` itself (tests do not build a `cdylib`), then compiles and runs `tests/c/abi.c`.

### `avulse-windivert-compat`: the WinDivert shim (Phase 4)

`crates/windivert-compat` builds `libavulse_windivert` (`[lib] name = "avulse_windivert"`, `cdylib` and `rlib`, the rlib for the tests). The platform-neutral core: `address.rs` (`WdAddress`, WinDivert's 80-byte `WINDIVERT_ADDRESS` with its bitfield word and union, `to_avulse`/`from_avulse`; at the NETWORK layers union bytes 8 to 63 carry the first `CONTEXT_KEPT` = 56 bytes of avulse's `Context`), `packet.rs` (WinDivert's own packet parser, `WinDivertHelperParsePacketEx`, which differs from `avulse_proto` on malformed packets) and `helpers.rs` (`hash_packet`, `calc_checksums`, `eval_filter`, `check_filter`, `format_filter` with WinDivert's results; `random*` reads WinDivert's hash seeded with the timestamp). `ebpfdivert.rs` (Linux, public for the integration tests) holds the `ebpfdivert_*` exports: libebpfdivert's API, negative errno values, no `catch_unwind` (as in capi, a panic aborts), a handle that counts calls in progress so that `close` waits for them. Only the symbols the bindings use are exported (`tests/symbols.rs` checks the list with `nm`). `src/tests/vectors.rs` is generated by `scripts/gen_compat_vectors.py`, which compiles a driver against ebpfdivert's vendored WinDivert helpers (`../ebpfdivert/src/wd/`); the tests also run WinDivert's 241 filter vectors through `eval_filter`. `tests/capture.rs` (`AVULSE_BPF=1`, root) drives the exports on `lo`. Differences from libebpfdivert are listed in `book/src/libraries/windivert-compat.md`; the bindings themselves are never changed to suit the shim. `Filter::format_windivert` (`crates/filter/src/windivert/parse.rs`, `Display` of the parse tree) is its `format_filter`, and `Filter::windivert_object` (`windivert/object.rs`, a port of WinDivert's compiler back end: simplify, flatten, emit, serialize) turns a WinDivert filter into WinDivert's `@WinDiv_…` object, which the shim reports as REFLECT's data. pydivert's and jdivert's suites pass against the shim unchanged (Step 21): pydivert's VM with `PYDIVERT_EBPFDIVERT_LIB`, jdivert's with `-Debpfdivert.skipDownload=true -Debpfdivert.local=…`, on JDK 25 and JDK 8; copy the library into the binding's folder, untracked, and remove it afterwards.

### `avulse-ebpf` (Spike A, Steps 7 to 11)

`bpf/tc.bpf.c` holds the static cls_bpf programs (section `classifier`, the name aya knows). `avulse_ingress` first redirects inbound injections that arrive on `lo` with `MARK_REDIRECT` (to the target's ingress, as `MARK_INJECTED`), whatever the configuration. `avulse_ingress_ip`/`avulse_egress_ip` are the same entry points for devices without a link-layer header (`classify(…, raw_ip)`: the packet starts at the IP header, whose version must agree with `skb->protocol`; NETWORK layers only); `Classifier::attach` takes the `Link` to pick them, and `BPF_PROG_TEST_RUN` cannot drive them (it always builds an Ethernet header), so only `tests/capture.rs` covers them. `avulse_ingress`/`avulse_egress` check the handle's configuration (`bpf/abi.h`, mirrored by `src/abi.rs`: layer, `CFG_*` flags, TC priority, heartbeat, `lo` ifindex), the marks and the layer, parse the headers with `avulse_proto::Packet`'s rules into per-CPU facts (`bpf/facts.h`, mirrored by `src/facts.rs`; `Facts::from_packet`, `Facts::at_network` for the NETWORK layers where the filter sees the IP packet from `base`, and `Facts::offloaded` for frames whose outer VLAN tag the device took off, parsed with one in-band tag less, are the contract), then tail-call the generated matcher (through `avulse_options` first when `CFG_TCP_OPTIONS` is set: it walks the TCP options into `facts.opts`, in a program of its own because the loop inlined in the parser went over the verifier's limit), which writes the verdict and tail-calls `avulse_act` (a tail call never returns). `avulse_act` drops, or copies the frame to the ring buffer (`struct avulse_record`, three size classes) and diverts or sniffs. Every failure passes the packet with `TC_ACT_UNSPEC` (fail-open, the next classifier runs), never `TC_ACT_OK`. The license string must stay `"GPL"` (the kernel's list has no LGPL/GPL dual, and `bpf_fib_lookup` is GPL-only); keep `abi.h`/`abi.rs` and `facts.h`/`facts.rs` in step (both sides assert sizes). `build.rs` compiles it with clang on Linux targets only. `codegen.rs` compiles the IR for an `Env` (the handle's layer, priority and interface names: `lower` decides handle constants, turns `iface` into `ifidx` and `local.*`/`remote.*` into conditionals on `outbound`) and returns `Error::Unsupported` for what it lacks; `superset`/`compile_superset` widen each unsupported test to the presence of the protocols of the Wireshark fields it reads (`icmp.seq == 1` to `icmp`), else `true` (`false` under a `not`), and `Matcher::exact` says whether user space must filter again (also false at ETHERNET when a filter reads link-layer bytes, for frames with an offloaded VLAN tag; `vlan.*`, `eth.type` and `frame.len` handle the offloaded tag, from `M_VLAN`/`M_VLAN_AD` and `facts.vlan_tci`, exactly). Numbers are 64-bit with a static range check (no overflow, no signed division: 5.15 lacks it); occurrences may be absent individually (VLAN tags, options), with a stack slot for `all`; sets over 4 items are trees of jumps; `insn.rs` assembles with forward labels and drops unreachable instructions, which the verifier rejects. `loader.rs` uses `aya` for the object and attaching (`Classifier::attach`, always `TcAttachOptions::Netlink`: aya's plain `attach` picks TCX on 6.6+), and raw `bpf()` for what aya lacks (loading raw instructions, setting a program array slot from an fd, `BPF_PROG_TEST_RUN`, and `HashMap`, the registry's pinned map). `bpf/events.bpf.c` (Step 14) holds the event programs of the FLOW and SOCKET layers: cgroup v2 root programs (`sock_create`, `post_bind4/6`, `connect4/6`, `sock_release`, `cgroup_skb`) and `sockops`, attached through links by `loader::Events` (`src/loader/events.rs`), with socket storage for each socket's PID, `comm` and endpoints, the TC programs' `struct avulse_config` (layer FLOW or SOCKET) and records of their own (`struct avulse_event` in `abi.h`, `abi::EventRecord`); the task's PID and name sit behind the load-time constant `avulse_have_task`. A SOCKET handle without SNIFF refuses binds and connects in the kernel (Step 16): `bind`/`connect` write the event's facts (`struct avulse_ev_facts` in `facts.h`, `facts::ev`, whose `flags`/`verdict` share the TC facts' offsets) and record to the per-CPU `avulse_ev_state`, then tail-call the matcher in the program array of their kind (`loader::EventHook`: connect4/6, post_bind4/6, one array, matcher and action program each, because a program array holds one program type); the action reports the event (`EV_BLOCKED`) and returns 0 to refuse. `codegen` has an event mode for `Env::event` at FLOW/SOCKET: `lower_event` decides every leaf that reads no field of the event with the bytecode interpreter on the empty packet (`constant`), turns `local.addr`/`remote.addr` into the stand-ins `ip.src`/`ip.dst` (IPv4-mapped) and `ipv6.src`/`ipv6.dst`, `operand(…, ev)` reads `event_scalar`/`event_regions` (`process.name` is `Region::FactStr`, its length the first NUL), `Gen::copy` copies facts bytes instead of `bpf_skb_load_bytes`, and the matcher returns 1 when it cannot reach the action; `decide_for` tells whether a filter can match an event. `tests/emu.rs` runs `common::EVENT_FILTERS` on `common::event_records()` against the evaluator. When extending the generator, add filters to `tests/common/mod.rs` (`SUPPORTED`, which `the_corpus_exercises_every_filter` requires to both match and miss; what must stay widened goes in `UNSUPPORTED`) and run the kernel test on both VMs: the 5.15 verifier is the strict one. The tests also run WinDivert's vectors and the tshark tables, which they include by path from `crates/filter/src/tests/` (`windivert_vectors.rs`, `filters.rs`).

Tests sit in `src/tests.rs` (proto) and `src/tests/` (filter: `mod.rs`, frame builders in `frames.rs`, a pcap writer, `tshark.rs`). They build frames by hand with helpers such as `eth()`, `ipv4()`, `tcp()` and `udp()`.

### `drivers/windows`: the Windows driver (Phase 5)

The user-mode side is `crates/avulse/src/backend/windows/` (Step 24): it installs and starts the `avulse` kernel service (from `AVULSE_DRIVER` or next to the executable, unless `NO_INSTALL`), opens `\\.\Avulse` overlapped, and receives through one in-flight `RECV` with a timeout (`CancelIoEx`); `crates/avulse/tests/capture_windows.rs` tests it in the VM (`test.ps1`). Check it compiles on the host with `RUSTC_BOOTSTRAP=1 cargo clippy -Zbuild-std=std,panic_abort --target x86_64-pc-windows-msvc -p avulse --all-targets --target-dir target/win`.

`drivers/windows/driver` is `avulse.sys` (package `avulse`, WDM, `no_std` Rust, outside the main workspace with its own `[workspace]`, `Cargo.lock` and `.cargo/config.toml` for `+crt-static`); `drivers/windows/test` is `avulse-driver-test.exe`, which drives it through `\\.\Avulse` (`avulse_abi::ioctl`) and runs WinDivert's filter vectors through `EVAL`. Both build only in the `windows` VM: `vagrant winrm windows -e -c "C:\avulse\drivers\windows\scripts\build.ps1"` (clippy `-D warnings`, `cargo wdk build --profile release`), then `…\test.ps1` (loads the driver as a kernel service, runs the test, checks the driver stops, runs `capture_windows.rs`, then installs the driver with `netcfg` as a lightweight filter and runs that suite again with `AVULSE_ETHERNET=1`, and checks no crash dump appeared; `AVULSE_TCP_PEER=10.0.2.2:<port>`, with `drivers/windows/scripts/tcp-sink.py` on the host, adds the large-send test). `wfp.rs` holds the WFP callouts (IP packet and forward layers; one WFP filter per handle and layer, weight from the priority, `rawContext` the handle's id in the `HANDLES` table) and classify (divert = copy + `BLOCK` with `ABSORB`); `inject.rs` sends (`FwpsInject*Async0`, one injection handle per family, the sender's priority as the injection context, which classify compares to skip packets from the same or lower priorities and mark impostors). `lwf.rs` is the ETHERNET layer (Step 27): an NDIS lightweight filter, registered only when the driver was installed with `avulse.inf` through `netcfg` (else ETHERNET opens get `STATUS_NOT_SUPPORTED`, and `capabilities()` checks the filter's NetCfg registry key). Each module (adapter) runs a priority-sorted snapshot of the ETHERNET handles on every NET_BUFFER (`process`); an NBL with a taken frame is completed or returned and its other frames go on as copies; the filter's own NBLs come from its own pool (not `inject.rs`'s: WFP's injected NBLs reach the filter too) and are freed in the completion handlers, and a pause waits for them; injected frames go through the handles below the sender's priority first, as impostors (the filter never sees its own sends). The 802.1Q tag and large sends (LSO) are out-of-band NBL info: the tag is put back into the frame the handles see, and `avulse_abi::ioctl::EthernetContext` in the address's context restores both on reinjection (`checksum::tcp_large_send` writes the partial TCP checksum). Free every static allocation at unload: Driver Verifier bugchecks on leaked pool (an emptied `BTreeMap` keeps its root node). After a crash, read `C:\Windows\MEMORY.DMP` with the WDK's `kd -z … -c "!analyze -v; kv; q"` and `vagrant reload windows` to remount `C:\avulse`. Release builds only, and keep per-packet code off the stack (`eval.rs`: per-processor scratch, `matches_in`, `KeExpandKernelStackAndCalloutEx` below 12 KiB). Bindings come from `build.rs` (bindgen over `ntifs.h`, `wdmsec.h`, `ndis.h`, `fwpsk.h`, `fwpmk.h`); add a function to its allowlist before using it, and remember that many WDK names are macros or inlines (`IoCreateDeviceSecure` is `WdmlibIoCreateDeviceSecure`, `KeRaiseIrql` is inline on x64). Format with `cargo fmt --manifest-path drivers/windows/driver/Cargo.toml`; type-check the test tool on the host with `RUSTC_BOOTSTRAP=1 cargo check -Zbuild-std=std,panic_abort --target x86_64-pc-windows-msvc` in `drivers/windows/test`. The steps are in `docs/implementation-plan.md` (Phase 5).

### `spikes/windows-driver` (Spike B)

A `windows-drivers-rs` WDM driver, outside the workspace (`exclude = ["fuzz", "spikes"]`, its own `[workspace]` and `Cargo.lock`), built only in the `windows` Vagrant VM with `cargo wdk build --profile release` (`scripts/build.ps1`, then `scripts/test.ps1`; see the `Vagrantfile` header). `build.rs` compiles its filters to bytecode and generates the NDIS/WFP bindings that `wdk-sys` lacks. `wfp.rs` holds the IPv4 packet-layer callouts, `lwf.rs` the NDIS lightweight filter, `stats.rs` the evaluation (on an expanded stack when less than 12 KiB is left: the x64 kernel stack is 24 KiB, and a debug build overflowed it) and the counters. Format it with `cargo fmt --manifest-path spikes/windows-driver/Cargo.toml`; the host cannot build it.

## Documentation and website

Published to <https://ffalcinelli.github.io/avulse/> by `.github/workflows/pages.yml`, which runs `scripts/build-site.sh`: `site/` (hand-written landing page; `playground.js` loads `crates/wasm` built by wasm-pack into `/pkg/`), `book/` (mdBook guide, `/guide/`), rustdoc (`/api/rust/`) and pdoc of `bindings/python` (`/api/python/`).

- The guide is the language reference. The README stays a short front page that links to it.
- Every public item needs docs (`missing_docs` is a workspace lint, so CI fails without them). CI's `docs` job runs rustdoc with `-D warnings`, clippy for `wasm32-unknown-unknown` and `mdbook build`.
- `crates/cli/tests/docs.rs` compiles every ```` ```filter ```` block in `book/src` and `README.md` (```` ```filter,error ```` blocks must fail; a blank line separates filters, except after `let` lines), and checks that `book/src/reference/fields.md` matches `avulse filter fields --format markdown`.

- `avulse-wasm` keeps `wasm-bindgen` behind `cfg(target_arch = "wasm32")`; its logic is plain Rust tested natively. When the language changes, update its samples' tests and, if useful, the playground's `EXAMPLES`.
