# Rust crates

Avulse is a Cargo workspace. The public Rust crates are:

| Crate | What it does |
| --- | --- |
| [`avulse-proto`](https://ffalcinelli.github.io/avulse/api/rust/avulse_proto/) | Zero-copy parsing and checksums. `no_std`, no `alloc`. |
| [`avulse-filter`](https://ffalcinelli.github.io/avulse/api/rust/avulse_filter/) | The filter language, bytecode verifier/interpreter and WinDivert front-end. `no_std` with `alloc`. |
| [`avulse-abi`](https://ffalcinelli.github.io/avulse/api/rust/avulse_abi/) | Shared ABI types (`Address`, `Flags`, `Param`, `Shutdown`, `Stats`, `Syntax`) and wire protocols. `no_std` with `alloc`. |
| [`avulse`](https://ffalcinelli.github.io/avulse/api/rust/avulse/) | Handles, flags, addresses and the Linux, Windows and macOS backends ([guide](handles.md)). |

None is on crates.io yet (only the `avulse` name is reserved there). Use them from Git:

```toml
[dependencies]
avulse-proto = { git = "https://github.com/ffalcinelli/avulse" }
avulse-filter = { git = "https://github.com/ffalcinelli/avulse", features = ["regex"] }
```

The API is not stable: pin a commit with `rev = "…"`.

## Parsing packets

`Packet::parse` takes a buffer and what it starts with, an Ethernet frame or an IP packet. It
never fails, allocates or panics: headers it cannot read are absent, and the rest of the buffer is
the payload. Each header is a typed view over the buffer.

```rust,ignore
{{#include ../../../crates/proto/examples/parse.rs}}
```

Run it with `cargo run -p avulse-proto --example parse -- [--ip] [HEX]`. After changing a packet,
`checksum::recalculate(&mut bytes, link)` fixes the IPv4, TCP, UDP, ICMP and ICMPv6 checksums.

## Matching filters

`Filter::compile` returns a filter or a `Diagnostic`, which `render` formats with the source line,
as the CLI does. `Filter::matches` takes a parsed packet and its `Meta`: direction, interface,
layer and the other [metadata](../filters/metadata.md). Compile once and match many times:
matching does not allocate.

```rust,ignore
{{#include ../../../crates/filter/examples/filter.rs}}
```

Run it with `cargo run -p avulse-filter --example filter -- '<filter>'`.

## `no_std`

`avulse-proto`, `avulse-filter` and `avulse-abi` are `#![no_std]` and `#![forbid(unsafe_code)]`,
and CI builds them for a bare-metal target (`thumbv7em-none-eabihf`). `avulse-filter` needs
`alloc` to compile filters, but not to verify or evaluate them, except for regular expressions.

| Feature | Crate | Effect |
| --- | --- | --- |
| `regex` | `avulse-filter` | `matches` / `~`, through `regex-automata` (still `no_std`) |
